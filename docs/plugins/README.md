## 1. Что такое плагин

Плагин добавляет Lora новые команды. Каждая команда работает двумя путями сразу:

- **без ИИ** — Lora узнаёт фразу по шаблону из вашего `plugin.toml` и вызывает команду мгновенно, офлайн;
- **через ИИ** — та же команда видна языковой модели как инструмент с описанием и схемой аргументов, и модель вызывает её, когда просьба сложнее шаблона.

Внешний плагин — это файл `plugin.wasm`, собранный из JavaScript. Он выполняется в песочнице WebAssembly (движок Extism на wasmtime):

- у плагина нет доступа к файлам, сети, буферу обмена и системе;
- всё, что ему нужно, он просит у Lora через **функции хоста** (`http_request`, `speak`, `kv_get`…);
- каждая функция проверяется по разрешениям, которые пользователь увидел и одобрил;
- падение или зависание плагина не роняет Lora: вызов вернёт ошибку, плагин перезапустится.

**Встроенные** модули (окна, звук, таймеры, Steam, Epic) написаны на Rust внутри Lora. Для маршрутизатора и ИИ они ничем не отличаются от внешних: и те, и другие лежат в одном реестре команд.

## 2. Быстрый старт

**Шаг 1. Инструменты.**

- [extism-js](https://github.com/extism/js-pdk/releases) 1.6+ — компилятор JavaScript → WebAssembly. Скачайте архив для своей системы, распакуйте и положите `extism-js` в `PATH`.
- [binaryen](https://github.com/WebAssembly/binaryen) — `wasm-merge` и `wasm-opt`. На macOS: `brew install binaryen`. На Windows: скачайте релиз и добавьте папку `bin` в `PATH`.

Проверка: `extism-js --version`.

**Шаг 2. Копия шаблона.** Скопируйте папку [`templates/plugin-js`](https://github.com/GRYurv/Lora-AI-Assistant/tree/main/templates/plugin-js) из репозитория [Lora-AI-Assistant](https://github.com/GRYurv/Lora-AI-Assistant) и переименуйте её, например в `hello`.

**Шаг 3. Код.** Откройте `src/index.js`:

```js
function hello() {
  const { args, lang } = lora.input();
  const name = args.name || (lang === "ru" ? "друг" : "friend");
  return lora.reply({ speak: lang === "ru" ? `Привет, ${name}!` : `Hello, ${name}!` });
}

module.exports = { hello };
```

**Шаг 4. Сборка.** В папке плагина:

```sh
./build.sh
```

Появится `plugin.wasm`. На Windows выполните команды из `build.sh` вручную в PowerShell:

```powershell
Get-Content src\lora.js, src\index.js | Set-Content dist\bundle.js
extism-js dist\bundle.js -i src\index.d.ts -o plugin.wasm
```

**Шаг 5. Установка.** Скопируйте папку плагина (нужны `plugin.toml` и `plugin.wasm`) в папку плагинов Lora — см. раздел 3. В Lora откройте **Настройки → Плагины и MCP**, примите предупреждение о внешних плагинах. Плагин появится в списке сразу, без перезапуска.

**Шаг 6. Проверка.**

- голосом: «Лора, привет плагин»;
- в терминале разработчика (**Настройки → Дополнительно → Режим разработчика**, затем ⌘⌥J / Ctrl+Shift+J): `say привет плагин` или `run my-plugin.hello {"name":"Роман"}`.

## 3. Папка плагина

```
my-plugin/
├── plugin.toml        # манифест (обязательно)
├── plugin.wasm        # собранный код (обязательно)
├── icon.png           # иконка 128×128 (по желанию)
├── README.md          # описание для пользователей (по желанию)
└── locales/           # переводы (по желанию)
    ├── ru/plugin.ftl
    └── en/plugin.ftl
```

Папка плагинов:

| Система | Путь |
|---|---|
| macOS | `~/Library/Application Support/com.gryurv.lora/plugins` |
| Windows | `%APPDATA%\com.gryurv.lora\plugins` |

Кнопка **«Открыть папку плагинов»** в настройках открывает её в Finder или Проводнике. Lora следит за папкой: новый или изменённый плагин подхватывается через секунду.

## 4. Справочник по plugin.toml

| Поле | Тип | Обязательно | По умолчанию | Описание |
|---|---|---|---|---|
| `id` | строка | да | — | Уникальный id: `a-z`, `0-9`, `-`, 2–64 символа. Пример: `weather` |
| `name` | строка | да | — | Название в списке плагинов |
| `version` | строка | да | — | Версия плагина, например `1.2.0` |
| `api` | число | да | — | Версия API Lora. Сейчас `1` |
| `description` | строка | нет | `""` | Одна строка о плагине |
| `author` | строка | нет | `""` | Автор |
| `os` | массив строк | нет | все | `["macos"]`, `["windows"]` или оба |
| `permissions` | массив строк | нет | `[]` | См. раздел 9 |
| `network` | массив строк | нет | `[]` | Домены для `http_request`: `["api.open-meteo.com"]` |
| `secrets` | массив строк | нет | `[]` | Имена секретов, которые плагин может читать (раздел 10) |
| `settings` | таблица | нет | — | JSON Schema настроек (раздел 10) |
| `[[commands]]` | массив таблиц | нет | — | Команды (раздел 5) |

Поля команды:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | строка | да | `a-z`, `0-9`, `_`. Совпадает с именем экспортируемой функции. Полный id команды — `<плагин>.<команда>` |
| `title` | `{ ru, en }` | нет | Название в списке команд и палитре |
| `description` | `{ ru, en }` | нет | Описание для ИИ: когда вызывать команду |
| `triggers` | `{ ru = [...], en = [...] }` | нет | Шаблоны фраз для локального распознавания |
| `examples` | `{ ru = [...], en = [...] }` | нет | Примеры фраз для классификатора |
| `args` | таблица | нет | JSON Schema аргументов |
| `dangerous` | логическое | нет | `true` — действие опасное, идёт через подтверждение |

Пример:

```toml
id = "weather"
name = "Погода"
version = "1.0.0"
api = 1
description = "Прогноз через Open-Meteo"
author = "Иван"
permissions = ["network"]
network = ["api.open-meteo.com", "geocoding-api.open-meteo.com"]

[[commands]]
id = "current"
title = { ru = "Погода сейчас", en = "Current weather" }
description = { ru = "Текущая погода в городе", en = "Current weather in a city" }
triggers = { ru = ["какая погода [в] [городе] {city}", "какая погода"], en = ["what's the weather [in] {city}", "what's the weather"] }
examples = { ru = ["какая погода в казани"], en = ["weather in london"] }
args = { type = "object", properties = { city = { type = "string", description = "Город" } } }
```

## 5. Команды и фразы-триггеры

Шаблон — это фраза с особыми вставками:

| Синтаксис | Значение | Пример |
|---|---|---|
| `слово` | обязательное слово | `какая погода` |
| `[слово]` | необязательное слово | `[пожалуйста] включи` |
| `(а\|б)` | одно из синонимов | `(включи\|запусти) музыку` |
| `[а\|б]` | необязательный синоним | `[поставь\|заведи] таймер` |
| `{name}` | свободный текст → аргумент `name` | `запиши {text}` |
| `{n:number}` | число → аргумент `n` | `громкость {level:number}` |
| `{unit=минут\|секунд}` | одно из значений → аргумент | `{n:number} {unit=минут\|секунд}` |

Как Lora готовит фразу перед сравнением:

- нижний регистр, `ё` → `е`, знаки препинания убираются;
- числа словами становятся цифрами: «двадцать пять» → `25`;
- слово-активатор в начале («Лора, …») отбрасывается;
- небольшие ошибки распознавания прощаются (нечёткое сравнение).

Советы для русского языка:

- **Падежи.** Пишите варианты окончаний через синонимы: `(погода|погоду|погоды)` или делайте окончание необязательным: `погод[а|у|ы]`.
- **Числа.** Достаточно `{n:number}` — «пять», «5» и «пятнадцать» превратятся в число.
- **Порядок слов.** Добавьте второй шаблон для другого порядка: `какая погода в {city}` и `в {city} какая погода`.
- **Конкретика.** Чем больше обычных слов в шаблоне, тем выше его приоритет. `открой погоду` победит общее `открой {app}`.

Если ни один шаблон не подошёл, Lora пробует классификатор по примерам из `examples`. Если и он не уверен, запрос уходит к ИИ. ИИ видит вашу команду как инструмент с именем `<плагин>__<команда>`, описанием из `description` и схемой из `args`.

## 6. Аргументы и JSON Schema

Аргументы описываются стандартной [JSON Schema](https://json-schema.org/) прямо в TOML:

```toml
args = { type = "object", properties = { city = { type = "string", description = "Город, например «Казань»" }, days = { type = "integer", minimum = 1, maximum = 7 } }, required = ["city"] }
```

- Имена в `properties` совпадают с именами вставок в шаблонах (`{city}`).
- `description` у каждого поля — подсказка для ИИ. Пишите её конкретно.
- Lora проверяет аргументы по схеме до вызова плагина. Если обязательного поля нет, плагин не вызывается, а пользователь получает понятную ошибку.
- Числа из `{n:number}` приходят числами, остальные вставки — строками.

## 7. Входные и выходные данные

**Вход.** `lora.input()` возвращает объект:

```json
{ "args": { "city": "Казань" }, "lang": "ru" }
```

**Выход.** Функция команды вызывает `lora.reply({...})` и возвращает её результат:

| Поле | Что делает |
|---|---|
| `speak` | Фраза, которую Lora скажет голосом (и покажет в чате) |
| `display` | Текст строки действия («Погода: +3°»). По умолчанию равен `speak` |
| `data` | Любые данные — их увидит ИИ или вызвавшая команда |
| `error` | Текст ошибки. Lora скажет «Не получилось: …» |

Стиль ответов Lora — коротко и в женском роде:

| Хорошо | Плохо |
|---|---|
| «Открыла», «Готово», «Записала» | «Открыто», «Выполнено успешно» |
| «Сейчас +3°, облачно» | «Текущая температура воздуха составляет…» |

## 8. Справочник API хоста

Все функции доступны через объект `lora` из `src/lora.js`. При ошибке они бросают исключение `Error`.

| Функция | Разрешение | Возвращает | Ошибки |
|---|---|---|---|
| `lora.log(message, level?)` | — | — | — |
| `lora.http(url, { method, headers, body })` | `network` + домен в `network` | `{ status, body }` | нет разрешения, домен не в списке, приватный режим, сеть |
| `lora.notify(title, body)` | `notifications` | — | нет разрешения |
| `lora.speak(text)` | — | — | — |
| `lora.kvGet(key)` | — | строка или `null` | — |
| `lora.kvSet(key, value)` | — | — | — |
| `lora.clipboardRead()` | `clipboard` | строка | нет разрешения |
| `lora.clipboardWrite(text)` | `clipboard` | — | нет разрешения |
| `lora.run(id, args)` | `system` для чужих команд | результат команды | нет разрешения, запрещено уровнем доступа |
| `lora.settings()` | — | объект настроек | — |
| `lora.secret(name)` | имя объявлено в `secrets` | строка или `null` | секрет не объявлен |

Примеры:

```js
lora.log("запрос погоды", "debug");               // уровни: debug, info, warn, error

const r = lora.http("https://api.open-meteo.com/v1/forecast?latitude=55.8&longitude=49.1&current=temperature_2m");
const temp = JSON.parse(r.body).current.temperature_2m;

lora.kvSet("last_city", "Казань");                // хранилище только этого плагина
const city = lora.kvGet("last_city");

lora.run("my-plugin.other", { x: 1 });            // свою команду можно без разрешений
lora.run("volume.set", { level: 30 });            // системную — только с "system"
```

## 9. Разрешения и безопасность

**Согласие.** Пока пользователь не нажал «Включить» в окне «Включить внешние плагины?», Lora не сканирует папку и не загружает ни одного `.wasm`. Согласие можно отозвать в **Настройки → Приватность → Внешние плагины**: все плагины сразу выгрузятся.

**Разрешения** показываются в списке плагинов и в карточке плагина:

| Разрешение | Что открывает |
|---|---|
| `network` | `lora.http` к доменам из `network = [...]` (поддомены тоже) |
| `clipboard` | чтение и запись буфера обмена |
| `notifications` | системные уведомления |
| `system` | вызов встроенных команд Lora (`lora.run`) |
| `media` | зарезервировано для музыкальных плагинов |
| `files` | зарезервировано; прямого доступа к файлам нет |

**Что плагину запрещено всегда:** читать и писать файлы, открывать сокеты, запускать программы, видеть данные других плагинов и ключи провайдеров ИИ.

**Опасные действия.** Отметьте команду `dangerous = true`, если она удаляет данные, что-то покупает, отправляет сообщения или меняет систему. Тогда она подчиняется уровню **Настройки → Приватность → Опасные действия**:

- «Не разрешать» — команда не выполнится;
- «Спрашивать подтверждение» — Lora спросит голосом и покажет окно «Выполнить / Отмена»;
- «Разрешать всегда» — выполнится сразу.

Пользователь может задать плагину свой уровень, но не выше общего. Через `lora.run` плагин не обойдёт эту проверку: вызванная команда проходит её заново.

## 10. Настройки и секреты

**Настройки.** Опишите их JSON Schema в `plugin.toml`:

```toml
[settings]
type = "object"
[settings.properties.units]
type = "string"
enum = ["metric", "imperial"]
default = "metric"
title = "Единицы"
```

Читайте их через `lora.settings()`:

```js
const { units = "metric" } = lora.settings();
```

**Секреты** (API-ключи, OAuth-токены) хранятся в системной связке ключей — Keychain на macOS, Credential Manager на Windows. В файлах они не лежат. Объявите имена:

```toml
secrets = ["api_key"]
```

и читайте:

```js
const key = lora.secret("api_key");
if (!key) return lora.reply({ error: "Добавь API-ключ в настройках плагина" });
```

Пример с музыкальным сервисом: плагин хранит OAuth-токен как секрет `token`, а `kvSet("expires_at", …)` запоминает время его истечения.

## 11. Отладка

1. **Настройки → Дополнительно → Режим разработчика** — в сайдбаре появится раздел «Разработчик».
2. Терминал открывается из сайдбара или клавишами ⌘⌥J / Ctrl+Shift+J.
3. В фильтре модулей выберите `plugin` — останутся строки ваших плагинов (`plugin:<id>`).

Полезные команды терминала:

| Команда | Что делает |
|---|---|
| `plugins list` | плагины, версии и ошибки загрузки |
| `plugins reload` | перечитать папку плагинов |
| `plugins info <id>` | манифест и разрешения |
| `route <фраза>` | какую команду выберет маршрутизатор |
| `run <плагин.команда> {json}` | вызвать команду напрямую |
| `commands <фильтр>` | найти команду в реестре |

Типичные ошибки:

| Сообщение | Причина | Что сделать |
|---|---|---|
| `invalid id` | недопустимые символы в `id` | только `a-z`, `0-9`, `-` |
| `unsupported api` | `api` не равен `1` | поставьте `api = 1` |
| `export «x» not found` | функция не экспортирована | добавьте её в `module.exports` и в `index.d.ts` |
| `permission «network» is not granted` | нет разрешения | добавьте в `permissions` |
| `domain … is not in the plugin's network list` | домена нет в `network` | добавьте домен |
| `timed out` | вызов дольше 10 секунд | ускорьте код, сократите запросы |

## 12. Локализация

Плагин может принести свои строки на русском и английском:

```
locales/ru/plugin.ftl
locales/en/plugin.ftl
```

Формат — [Fluent](https://projectfluent.org/). Называйте ключи с префиксом плагина, чтобы они не пересекались с чужими: `weather-sunny = Солнечно`. Фразы-триггеры задаются отдельно для каждого языка прямо в `plugin.toml` (`triggers = { ru = [...], en = [...] }`). Язык пользователя приходит во входных данных: `lora.input().lang`.

## 13. Производительность

- **Лимиты:** 64 МБ памяти и 10 секунд на один вызов.
- **Размер:** пустой плагин на JS весит около 2,5 МБ. Это нормально: внутри движок QuickJS. Не тяните большие библиотеки, если хватает пары функций.
- **Сеть:** кэшируйте ответы через `kvSet` и не делайте больше 1–2 запросов на команду.
- **Скорость:** локальная команда должна отвечать за доли секунды. Долгие операции лучше вынести в ИИ-сценарий или разбить.
- Плагин компилируется один раз при загрузке. Повторные вызовы быстрые.

## 14. Версии API

`api = 1` в манифесте фиксирует контракт: функции хоста, формат входа и выхода, поля `plugin.toml`. Когда появится `api = 2`, плагины с `api = 1` продолжат работать без изменений. Новые возможности будут добавляться так, чтобы старые плагины их просто не использовали.

Список изменений API ведётся в этом документе.

| Версия API | Lora | Изменения |
|---|---|---|

## 15. Публикация

Каталог сообщества — это файл `catalog.json` в публичном репозитории `GRYurv/lora-plugins`. Lora показывает его в **Настройки → Плагины и MCP → Каталог**, но только если внешние плагины включены, нет приватного режима и есть интернет.

1. **Подготовьте плагин:** `README.md` (что делает, какие разрешения и зачем) и `icon.png` 128×128.
2. **Соберите архив** с `plugin.toml`, `plugin.wasm`, `README.md`, `icon.png`, `locales/`:
   ```sh
   zip -r weather-1.0.0.zip plugin.toml plugin.wasm README.md icon.png locales
   ```
3. **Посчитайте SHA256:**
   ```sh
   shasum -a 256 weather-1.0.0.zip      # macOS
   certutil -hashfile weather-1.0.0.zip SHA256   # Windows
   ```
4. **Опубликуйте архив** в Releases своего репозитория.
5. **Откройте pull request** в `GRYurv/lora-plugins` с записью в `catalog.json`:
   ```json
   {
     "id": "weather", "name": "Погода", "author": "Иван", "version": "1.0.0", "api": 1,
     "description": "Прогноз через Open-Meteo", "permissions": ["network"],
     "url": "https://github.com/ivan/lora-weather/releases/download/v1.0.0/weather-1.0.0.zip",
     "sha256": "…"
   }
   ```

**Правила проверки:** разрешения соответствуют описанию, домены в `network` нужны для работы, нет сбора данных без явного объяснения.

**Снятие.** Плагин с подтверждёнными жалобами убирается из `catalog.json`. У пользователей Lora помечает установленную копию как «снят с каталога» и предлагает выключить, но не удаляет сама.

Установка из каталога делает то же, что ручная: скачивает архив, сверяет SHA256, показывает разрешения и копирует папку в папку плагинов.

## 16. Готовые примеры

### Подбросить монетку (без сети)

Полный код: `plugins-examples/coin-flip`.

```js
function flip() {
  const { lang } = lora.input();
  const heads = Math.random() < 0.5;
  const count = Number(lora.kvGet("count") || 0) + 1;
  lora.kvSet("count", count);
  return lora.reply({ speak: lang === "ru" ? (heads ? "Орёл." : "Решка.") : heads ? "Heads." : "Tails.", data: { heads, count } });
}
module.exports = { flip };
```

### Погода (http_request и настройки)

`plugin.toml` — как в разделе 4. `src/index.js`:

```js
function current() {
  const { args, lang } = lora.input();
  const city = args.city || lora.kvGet("city") || (lang === "ru" ? "Москва" : "London");
  const geo = JSON.parse(lora.http(`https://geocoding-api.open-meteo.com/v1/search?count=1&language=${lang}&name=${encodeURIComponent(city)}`).body);
  const place = geo.results && geo.results[0];
  if (!place) return lora.reply({ error: lang === "ru" ? `Не нашла город ${city}` : `Couldn't find ${city}` });
  const w = JSON.parse(lora.http(`https://api.open-meteo.com/v1/forecast?latitude=${place.latitude}&longitude=${place.longitude}&current=temperature_2m`).body);
  const t = Math.round(w.current.temperature_2m);
  lora.kvSet("city", city);
  const text = lang === "ru" ? `В городе ${place.name} сейчас ${t > 0 ? "+" : ""}${t}°.` : `It's ${t}° in ${place.name}.`;
  return lora.reply({ speak: text, display: `${place.name}: ${t}°`, data: { temperature: t } });
}
module.exports = { current };
```

### Заметка в буфер обмена (разрешение clipboard)

```toml
permissions = ["clipboard"]

[[commands]]
id = "copy"
triggers = { ru = ["скопируй {text}"], en = ["copy {text}"] }
args = { type = "object", properties = { text = { type = "string" } }, required = ["text"] }
```

```js
function copy() {
  const { args, lang } = lora.input();
  lora.clipboardWrite(args.text);
  return lora.reply({ speak: lang === "ru" ? "Скопировала." : "Copied." });
}
module.exports = { copy };
```

### Опасное действие с подтверждением

```toml
permissions = ["system"]

[[commands]]
id = "clear_notes"
title = { ru = "Очистить черновики", en = "Clear drafts" }
triggers = { ru = ["очисти черновики"], en = ["clear drafts"] }
dangerous = true
```

```js
function clear_notes() {
  // Сюда Lora пустит только после подтверждения (или при уровне «Разрешать всегда»).
  lora.kvSet("drafts", "[]");
  return lora.reply({ speak: lora.input().lang === "ru" ? "Очистила черновики." : "Drafts cleared." });
}
module.exports = { clear_notes };
```

## 17. Шаблон

Папка `templates/plugin-js` — готовая основа:

| Файл | Назначение |
|---|---|
| `plugin.toml` | манифест с одной командой `hello` |
| `src/index.js` | код команд |
| `src/index.d.ts` | список экспортов и функций хоста для компилятора |
| `src/lora.js` | обёртки над API хоста (не меняйте) |
| `build.sh` | сборка `plugin.wasm` |

Добавляя команду, сделайте три вещи: опишите её в `plugin.toml`, напишите функцию в `src/index.js` и добавьте её в `module.exports` и в `declare module "main"` в `src/index.d.ts`.
